## 二、与番茄的关键差异（必读）

1. **登录方式不同**：番茄为扫码登录，七猫为手机验证码或账号密码登录。无法复用番茄的 `login_fanqie.js` 扫码流程，需要单独实现七猫登录脚本。
2. **协议复选框**：七猫登录前必须勾选同意协议复选框，否则登录按钮可能不可点击。
3. **URL 路径前缀**：七猫使用 `/front/...`，番茄使用 `/main/writer/...`，选择器与导航逻辑不可直接套用。
4. **session 持久化策略**：推荐使用 cookie 导入方式（参考番茄的 `session:extract-cookies` / `session:import-cookies` 流程），避免每次都走验证码登录。

## 三、发布工作流程

### 步骤 1：登录（已验证 URL，交互待侦察）

- 导航至登录页：`https://zuozhe.qimao.com/front/register-login/login?redirect=%2Ffront%2Findex`
- 选择登录方式：
  - **手机验证码登录**：输入手机号 → 获取验证码 → 输入验证码
  - **账号密码登录**：切换到密码登录 Tab → 输入账号密码
- **必须勾选**"同意协议"复选框
- 点击登录按钮
- 登录成功后应跳转至 `https://zuozhe.qimao.com/front/index`

> **待侦察**：登录按钮文本、Tab 切换控件、验证码输入框的具体结构、协议复选框的 selector。需登录后通过 DevTools 确认。

### 步骤 2：进入作品列表（已验证 URL）

- 直接导航：`https://zuozhe.qimao.com/front/book/list`
- 或从首页点击"作品管理"入口

> **待侦察**：作品卡片/列表项的 DOM 结构、点击进入某本书章节管理的链接格式。

### 步骤 3：进入目标作品的章节管理（待侦察）

- 在作品列表中点击目标作品
- 进入章节管理页面（URL 推测为 `/front/book/<bookId>/chapter` 或类似，**待侦察确认**）

> **待侦察**：
> - 章节管理页 URL 模式
> - 是否存在"分卷"概念（番茄有分卷，七猫待确认）
> - 章节列表的表格结构、状态列文本（如"审核中"/"已发布"等是否一致）

### 步骤 4：新建章节（待侦察）

- 在章节管理页点击"新建章节"按钮
- 进入章节编辑器页面

> **待侦察**：
> - "新建章节"按钮的文本与位置
> - 编辑器页 URL 模式
> - 是否需要先选择分卷（若七猫有分卷概念）

### 步骤 5：填写章节内容（待侦察）

按以下顺序填写：

1. **章节号**（若有独立输入框）
2. **章节标题**
3. **正文内容**

> **待侦察**：
> - 章节号是否为独立输入框，还是与标题合并（番茄是分开的）
> - 标题输入框的 placeholder
> - **正文编辑器类型**：可能是 `<textarea>` 或 `[contenteditable="true"]`，两种都要支持
> - 是否有引导/新手教程弹窗需要先关闭

### 步骤 6：存草稿（待侦察）

- 点击"存草稿"按钮
- 确认字数统计不再为 0

> **待侦察**：
> - "存草稿"按钮文本与位置
> - 是否有自动保存机制（可能无需手动存草稿）
> - 字数统计显示位置

### 步骤 7：发布（待侦察）

- 点击"发布"或"下一步"按钮
- 处理可能出现的中间弹窗（错别字检测、风险检测等，**待侦察确认是否存在**）
- 在最终发布弹窗中：
  - 确认章节标题、分卷（若有）
  - **是否有"是否使用AI"选项待侦察**（番茄必须选"否"，七猫待确认）
  - 选择立即发布或定时发布
  - 点击"确认发布"

> **待侦察**：
> - 发布按钮文本（"发布"/"下一步"/"提交"）
> - 中间弹窗种类与文本
> - 最终发布弹窗的字段
> - 是否有 AI 声明选项
> - 定时发布的设置控件

### 步骤 8：发布后验证（待侦察）

- 返回章节管理页
- 确认目标章节行存在
- 确认状态为"审核中"或"已发布"（**状态文本待侦察确认**）

## 四、平台特有注意事项

### 4.1 登录态保持
- 七猫登录态会过期，需定期重新登录或刷新 cookie
- 推荐工作流：在 GUI 浏览器登录 → 提取 cookie → 导入到 headless 环境 → 用 cookie-only 模式发布

### 4.2 验证码登录的限制
- 手机验证码登录依赖人工接收短信，自动化脚本无法独立完成
- 建议采用"人工登录 + cookie 持久化"策略，避免每次发布都走验证码流程

### 4.3 协议复选框
- 登录前必须勾选"同意协议"复选框，否则登录按钮可能 disabled
- 自动化脚本需显式勾选，不能假设默认已勾选

### 4.4 编辑器类型不确定
- 七猫编辑器可能是 `<textarea>`（简单）或 `[contenteditable="true"]`（富文本）
- 实现时两种都要覆盖，优先尝试 contenteditable（与番茄一致），降级到 textarea
- CJK / emoji / 换行 round-trip 校验同样适用，不可降级

### 4.5 字数限制
- 七猫每日发布字数上限**待侦察确认**（番茄为 50,000 字/天）
- 在未确认前，保守起见沿用番茄的 50,000 字/天上限

## 五、安全发布协议（参照番茄）

1. **预览优先**：先用 `prepare_chapters.py --preview` 验证章节解析
2. **Fill-only 干跑**：填写编辑器但不提交，人工核对章节号、标题、正文
3. **最终发布弹窗 ≠ 已发布**：`确认发布` 点击才是真正提交，弹窗内字段需逐一核对
4. **发布后必须验证**：返回章节管理页确认行存在且状态正确
5. **定时发布注意**：定时章节在发布时间前约 30 分钟可能不可修改（沿用番茄约束，**七猫实际阈值待侦察**）

**永远不要**在未做发布后验证的情况下报告成功。

## 六、状态区分（与番茄对齐）

| 状态 | 含义 |
|------|------|
| `preview-only` | 仅解析预览，未做任何发布动作 |
| `fill-only` | 编辑器已填写，未点击提交 |
| `to-final-modal` | 到达最终发布弹窗但未确认 |
| `submitted-unverified` | 已点击提交，但章节管理页未找到目标行（**非成功**） |
| `published-verified` | 已提交且章节管理页确认目标行状态正确 |
| `login-expired-or-timeout` | 登录态过期或验证码登录超时 |
| `input-validation-failed` | Unicode round-trip 或其他输入校验失败 |
| `error` | 其他异常 |
